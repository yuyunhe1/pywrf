# 临时公网风场加载优化验收

日期：2026-11-12。范围为新版平台、独立测试脚本及证据；旧版平台、原始 V3 和服务器 WRF
生产配置未在本次修改。资源限额沿用前次适度限制，未为加速而缩小搜索范围或抽稀气象源网格。

## 已交付行为

- 单时刻地图及经典算法回放改用同一个无损 U/V 数据包，浏览器由该包同时生成热力图和粒子场。
  新接口 `GET /api/wind/frame` 支持所选批次、整数预报分钟和修订身份，或冻结 `dataset_id + at`。
  `GET /api/wind/frames` 只接受同一数据集的一至两次重复 `at=`，每帧独立报告数据是否可用。
  旧 JSON 接口继续兼容；V3 冻结材料仍使用其原回放接口。
- 协议为 `application/vnd.wind-frame.v1`，包含小端长度、JSON 元数据和对齐数值数组。
  仅当 Float64→Float32→Float64 完全一致时采用 Float32，否则保留 Float64；缺失值不变。
  后端显式协商 gzip，提供 ETag/304；只有绑定修订或不可变数据集的请求可使用 immutable 缓存。
  指定批次不会被同有效时刻的另一批次替代，修订冲突明确返回 409。
- 最新 100m WRF 批次用一个前台优先的后台线程准备；其他高度先准备所选及随后两帧。
  原生 NPZ 首次解码、快照复制和 mmap 复用分项计量，已验证的源文件登记可跨重启复用。
  250–350m 平均层沿用原公式及缺测语义，改用向量化计算。
- 回放先采用已有的有效经典算法航程，不等待窗口计算。窗口更新不因临时路线 ID 变化而重置播放。
  绘制及历史固定路径仍选最早已确认窗口；后台窗口不会改变其空间路径。
- 自动回放时慢请求继续完成，后续目标合并；手动拖动取消旧请求。飞机推进、暂停不等待背景下载。
  新帧实际首次绘制后才更新背景时间和点查询材料，准备期间保留旧图；错误和缺帧明确显示。
- 图表在需要显示航线曲线时才加载，生产首屏不下载 ECharts。
- 前端默认生产构建，成功后原子登记版本；运行进程固定使用启动时的构建目录。
  失败构建不覆盖可用版本，保留前一版本及开发启动方式。API 和拥有者 WebSocket 保持同源代理。
- 修复 Windows 并发内存查询中的 ctypes 参数类型竞争，新增并发压力回归；限额数值不变。

## 保留的限额

| 项目 | 生效设置 |
| --- | --- |
| 搜索时间标签 | 合计 600000 |
| 搜索子进程 | 最多 4 个，两个起飞时刻各一对正反向进程 |
| 内存保护 | 系统可用物理内存余量 2048MB，搜索／协调进程常驻内存阈值 2048MB |
| 工作流预算 | 父任务 7200 秒，原指定起飞时刻首解阶段 60 秒 |
| 后台显示缓存 | 每进程、每来源合计 64MB：解码 48MB＋编码 16MB |
| 页面缓存 | 请求 48MB／24 项；回放 16MB／8 项 |
| 页面风场请求 | 合计最多 2 个活跃请求，预加载最多占 1 个 |
| 回放预加载 | 随后两帧；粒子背景每 30 飞行分钟更新 |
| 粒子显示 | 一套共享引擎，最多 6000 粒子／250000 屏幕投影采样位置 |
| 预处理 | 一个后台线程、最多 4 个待处理工作；检查内存，前台请求优先 |

内存保护为协作式检查，非操作系统硬配额。缓存限额不包含当前画面、投影场和活跃任务持有的
数组／不可变文件快照；不能据此宣称整个后端或浏览器只使用 64MB。mmap 为磁盘派生缓存，
首次压缩源变量解码仍可能读取整幅变量，不宣称是局部磁盘读取。

## 真实数据结果

`verify_public_wind_frames.py` 在真实原生 WRF 2026-11-11 06 UTC 批次上，分别抽取 3 个时次，
对旧回放 JSON 与新包使用相同 gzip level 4 比较，并逐项核对完整 U/V，包括 NaN。

| 高度 | 旧压缩 JSON | 新压缩包 | 体积减少 | 数值类型 |
| --- | --- | --- | --- | --- |
| 100m AGL | 185672–187749 字节 | 74149–74669 字节 | 60.04%–60.23% | Float32，精确往返 |
| 250–350m AGL 平均层 | 187539–189686 字节 | 105619–109451 字节 | 42.30%–43.51% | Float64 |

所有风矢量与原 JSON 逐值相等。平均层为保留精度使用 Float64，没有将其误报为同样减少 60%。
原生帧边界 10:00、10:03、10:09:59 相同，10:10 切换；缺帧、帧内保持和覆盖限制均有回归。
真实 GFS 新包可用，继续使用 `HOURLY_UV_TEN_MINUTE_HOLD_V1`，未改动其时间模型。

本机首次建立约 107.9km 航程资料的记录为 100m 约 0.72 秒、平均层约 1.43 秒。
单次公网数据请求记录：单包约 1.37 秒、双帧包约 1.00 秒；条件请求为 304、正文 0 字节。
这不是受控的改造前后延迟比较，也不是延迟分位数或服务时限。

100m 最新完整批次的 289 帧后台准备记录为约 15.05 秒、错误 0，只有一个工作线程；
后续自动同步至 12 UTC 批次亦完成 289 帧、错误 0。准备在后台进行，不是页面需要等待的总时间。
