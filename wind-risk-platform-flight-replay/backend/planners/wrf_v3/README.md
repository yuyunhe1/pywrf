# 平台 V3 规划适配

`vendor/` 是交付清单主版本的完整依赖快照：144 个 Python 文件、4 个配置 JSON。
目录层级与源代码相同，逐文件原路径和 SHA256 写在 `UPSTREAM_MANIFEST.json`。
源目录 `D:/yyh/wind_aware_flight/` 不作修改。工作进程每次启动核对副本哈希，自动测试同时核对原件。

平台请求经 `app/v3_service.py` 进入独立数值进程 `adapter/worker.py`，使用平台自己的任务 UUID、
原生预报批次、数据哈希与轨迹标识。没有调用原 CLI 历史任务登记，也没有启动执行、恢复或在线接管流水线。

| 文件 | 作用 |
| --- | --- |
| `adapter/planner.py` | 候选顺序、原 F0 打靶数学、0.9 初始转率余量、平台评分及渐进发布 |
| `adapter/free_core.py` | 自由起终点航向的零转率 / 小转率候选，仅求位置；廉价初值之后使用原风位移积分器校正 |
| `adapter/corridors.py` | 优先生成原生 MSL 避风走廊，过滤风切变/高度不明网格并按候选 ETA 修正 |
| `adapter/position_core.py` | 离线转弯/直飞打靶，保留上一段实际机头航向；控制与空速沿用 V3 参数 |
| `adapter/validation.py` | 调用原独立物理重积分，应用平台 1 米终点位置容差，保留航向、控制和非终点切换节点约束 |
| `adapter/native.py` | 原生空间、垂直插值与相邻 UTC 小时插值；四角数组缓存、原生区间和梯度界 |
| `adapter/curve.py` | 独立位移积分，保存连续 DOP853 多项式；不以地图抽稀折线代替真实曲线 |
| `adapter/geometry.py` | 连续曲线对原生区域边界的 2 米足迹检查；地形交给原生风场区间检查 |
| `adapter/certificate.py` | 固定曲线、固定空速的整个起飞区间检查、细分和保守窗口合并 |
| `adapter/profile.py` | 同一空间曲线按新的起飞时间重求实际经过时间、补偿航向、风险和地速 |
| `adapter/frame.py` | 在同一 MSL 高度及同一版本上生成地图风场 |
| `app/v3_native.py` | 原生文件独立镜像、来源批次隔离、不可变哈希文件及数据版本快照 |

先执行避风走廊搜索，再尝试零转率、小转率或多段转弯/直飞连接。原平台搜索只提供引导点；
实际连接仍使用原生时空风场求解、累计真实飞行时间，并对拼接后的整条路线重新验收。
只在搜索后比较原生直连提示的代价，避免粗引导网格的边界余量造成无必要的短程绕行；
直连也必须通过完整物理与连续约束验收。仅在统一积分策略代价改善时替换，没有全局最优保证。

多段路线按原生水平网格、垂直层选择和 UTC 小时边界拆分相同 ZOH 控制，利用连续曲线计算
控制节点，再执行原独立 C。此过程不改变控制值、实际空间路径或原中间节点门限。
它避免把风场插值导数的变化放在长积分步内部产生累计误差；原验证器和原代码文件均不修改。
回执记录实际 `numerical_max_step_s`，必要时使用原验证器的 0.1 秒默认步长复核。

1 米容差是用户授权的平台策略，**不是对原验证代码的修改**。回执记录 `upstream_valid`、
`upstream_failures` 和 `upstream_thresholds`，以及新的 `PASSED_PLATFORM_ENDPOINT_1M` 状态；
原严格验收失败时不能表述为原严格验收通过。非终点切换节点、航向和转率限制保持原规则。
自由航向初值求解以厘米级目标停止，最终空间曲线和独立物理重积分都必须落入 1 米半径。

数值优化保留原生插值，不缓存或冻结插值后的风矢量。内部时间使用相对任务秒数，避免直接
累加大 UTC 时间戳产生的浮点抖动；连续曲线使用相对位移积分，减少长航线绝对坐标误差。
过短而无法推进浮点时钟的控制段不会生成重复的多项式区间。

未来窗口固定保存的空间曲线与 MSL 高度，允许机头航向随风补偿，重新计算正向地速、到达时间
及转率。区间算法对曲线与 WRF 插值模型计算保守边界；未确认区间不列为可飞，展示边界向内取整。
这是平台新增的数值验证，不能套用原 V3 执行仿真的完整任务成功结论。

复制的依赖中有名称含 recovery 的模块；适配仅使用其中的初始连接数学，不调用执行恢复、
植入偏差、控制器或接管流水线。发布首解前和工作进程结束时均检查禁止加载的执行模块，
回执中的 `planning_activity` 记录规划模式与空的执行模块列表。

运行方式、环境变量和 HTTP 接口见平台根 README。验证结果与复现命令见 [VALIDATION.md](VALIDATION.md)。
