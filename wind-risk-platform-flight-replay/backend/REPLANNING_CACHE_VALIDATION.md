# 连续重规划、页面缓存与无效绕行过滤验收

2026-11-11。仅修改新版代码与隔离测试材料；不向正常航线数据库写入测试记录。

## 发现的问题与处理

原界面发出取消后没有等待 `compute_finished`，快速重规划会与尚未退出的旧计算重叠。
创建 POST 的网络响应若被中止，页面还可能不知道应取消哪个任务 ID。
此外，接合生成器保留协调器引用、天气边缓存形成循环引用，取消后的搜索树等待垃圾回收；
校验线程原先以 `shutdown(wait=False)` 退出，任务状态可能先于实际校验完成。

页面现在以独立拥有者标识和递增 `client_request_sequence` 统一管理指定规划与推荐。
新请求先取消旧请求并轮询实际退出，再开始计算；服务端保存取消序号，拒绝迟到创建及乱序
旧请求，重复 POST 同序号复用任务。`DELETE /api/route/planning-clients/{client_id}` 可以取消
尚未返回 ID 的请求，`forget=true` 同时释放旧结果、剖面、工作流及其 JSON 签名。
旧脚本未传序号时仍使用原生命周期；其他页面的任务不受影响。

协调器和方向进程显式关闭接合生成器，清理搜索标签、索引及天气边循环；简化器关闭迭代器，
校验线程响应停止信号后被等待退出。两个空闲方向进程保留供复用，不能把“进程仍在”误判
为“旧搜索仍在运行”。失联回收也释放带页面序号的活跃任务结果。

## 页面缓存

`frontend/src/utils/pagePlanning.js` 提供 LRU 内存缓存，上限 24 项／4MB，只保留准确路径和
轻量元信息，不保留搜索树、样本曲线、窗口及整个剖面，不使用 localStorage/sessionStorage。
匹配包含有序起终点、数据源、高度、所选批次和底图时刻、预报文件修订、后端运行 ID、算法、
机型、策略、速度、起飞时间、风速及切变阈值。

每次复用先请求轻量 `/api/times` 核对版本，然后使用所选批次重新生成完整航程剖面。
“现在起飞”使用其 `server_time`，避免复用旧起飞时间或依赖访客时钟；原显式批次继续传入
剖面加载器，不静默改成最新批次。硬约束不通过、数据不足或版本不匹配时继续正常搜索。
该复核只处理本次航程，未来窗口仍独立计算。

更换策略／时间的首次请求可携带最多四条相关缓存几何作为 `seed_routes`，端点和长度有
请求校验，服务端仍按本次实际经过时间、完整闭网格接触及策略代价独立验收。旧几何不是
当前最优证明。相同设置命中后提供“重新优化航线”，先保留已复核缓存路线，结束时显示
本次保留结果。普通新搜索保持 30 秒／结束时的原发布节奏；尚未显示的已验收候选也可缓存。

`pagehide` 清空缓存并递增代数，迟到回调不能重新写回；关闭时以 keepalive 释放服务端材料，
活跃任务在通知丢失时沿用 60 秒失联兜底。新页面或往返缓存恢复后使用新拥有者身份。
用户已保存的记录不随缓存清除。

## 绕行过滤

`app/detour_filter.py` 仅用于固定路线绕行建议。对原 A→B 与建议段获取闭网格集合，包括
沿边与零时长角点接触。完全相同的覆盖直接丢弃；不同格点若所有可用小时 U/V 精确相同，
也不作为新的避风选择。不会四舍五入风矢量，任何未来小时的差异都继续验收。
缺测／覆盖不足不作为相同的证据；建议若移除原有接触网格，保留正常验收以免丢掉避开
危险角点的实际改善。通过该过滤仍必须复核整条路径及下游延迟，并确认窗口收益。

对原段完全位于一个网格的情况，用允许总里程与 A 到网格内部边界的距离下界比较。
若所有顶点都不可能抵达边界，则所有连接线也在同一矩形网格内，直接在基线窗口评估后
结束并提示“无需绕行”。这只跳过已证明无空间风场差异的建议，不限制普通时空搜索的
不同时刻标签、回访及有效后缀。
